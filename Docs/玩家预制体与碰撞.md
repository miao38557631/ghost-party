# 可编辑玩家预制体与实体阻挡

## 编辑入口

统一玩家预制体：Assets/Prefabs/Player/GhostPlayer.prefab。

- 控制根节点：GhostPlayerMotor、CharacterController、GhostPlayerVisibility、原有 Light；运行及场景实例名为 InvisibleGhost。
- Visual：嵌套复用 Assets/Resources/Player/GhostVisual.prefab，保留当前 SpriteRenderer、Animator、镜头朝向及左右 flipX。更改美术可进入嵌套 Visual 预制体编辑。
- 速度在根节点 GhostPlayerMotor 的 Move Speed 调整（默认 4.5）。碰撞体尺寸在 CharacterController 调整。当前根缩放保留 0.76，Controller 高 1、半径 0.45，世界高度约 0.76、半径约 0.342；不靠翻转根缩放调整朝向。
- 美术高度、漂浮偏移、朝向与动画倍率仍在 Visual 的 GhostPlayerVisual 编辑。

## 固定场景实例

Level01_FirstFloor、Level02_SecondFloor 和 SampleScene 均保存一个统一预制体实例。WhiteboxPlayable 的 player/camera/交互目标，以及 GhostPartyPrototype 的 ghost 均使用序列化引用。正常进入 Play 尊重已保存玩家的 Transform 和预制体参数；跨楼层到达时才显式传送至楼梯附近。

GhostPlayerAvatar.Create 优先复用 InvisibleGhost，不再创建球体、添加临时外观或覆盖已有玩家配置。确需运行时生成时，通过 Resources/Player/GhostPlayerDefinition.asset 引用并实例化同一个 Assets/Prefabs/Player/GhostPlayer.prefab，不复制第二份玩家预制体。

编辑器菜单 Ghost Party > Player > Build Player Prefab and Bind Scenes 可执行绑定。它先备份已加载场景（含未保存编辑），再保存三张指定场景；重复运行不重置已存在预制体的参数、Visual 或 GUID，也不会重建房间。后续如果使用旧白盒生成器重新生成整个场景，可重新执行绑定菜单。

## 根因与修复

原玩家只有普通 SphereCollider，没有 Rigidbody 或 CharacterController；WhiteboxPlayable 和旧原型分别直接改写 transform.position。这种移动没有执行实体碰撞求解，墙上存在 BoxCollider 也无法阻止穿越。检查发现墙与玩家均在 Default Layer，碰撞矩阵允许接触，并非 Layer 被禁用。一楼 21 段、二楼 17 段墙体均已有实体碰撞体，无须重建墙体或修改碰撞矩阵。

现统一使用 3D CharacterController.Move，保留 2.5D 漂浮玩法（高度不再固定，见下节），不新增 Rigidbody 或第二套输入。较大位移分成不超过 0.2 世界单位的扫掠，沿墙滑动交给 CharacterController。Step Offset 为 0，避免把矮障碍当作台阶跨越。正常移动不再直接写玩家 Transform；场景到达/附身返回使用统一 Teleport，暂时关闭再恢复 Controller 并同步物理变换。

附身成功、挑战重试、完成/挣脱/Esc 返回继续复用现有流程。SetVisible 只控制外观及随身显示效果，不禁用 InvisibleGhost、CharacterController、Motor 或交互组件。旧原型的隐藏特写不再把控制根移动到临时演出坐标。

## 漂浮跟地（一楼凹陷舞池）

- 玩家仍然是**不落地**的漂浮鬼：根节点没有重力，`GhostPlayerMotor` 只负责让高度跟着脚下地板走。每帧在根节点上方 `Probe Above` 处向下打一条射线，取最高的一块可行走面（法线 y ≥ `Min Floor Normal Y`），把根节点稳定在「地板高度 + `Hover Height`」。默认 0.5 正好等于原来的固定平面（地板 -0.12 + 0.5 = 0.38），所以平地画面上看不出跳变。
- 高度用 `SmoothDamp` 过渡（`Follow Smooth Time` 0.12s，`Max Vertical Speed` 5 m/s）：从平层走进凹陷是缓缓沉下去，走出凹陷再浮起来，不会瞬移。只有落差超过 `Snap Distance`（默认 2.5m，例如传送/切楼层）才直接吸附到目标高度。
- 探测只认**地板根节点**上的碰撞体，家具、装饰、角色不算地板。地板来源按优先级解析：① 玩家根节点 `Floor Roots` 里手挂的对象；② 场景里挂了 `GhostFloorSurface` 组件的对象；③ 名字里含 `floor` / `地板` / `地面` 的根节点（例如 `1_Floor`），以及旧名字（`一楼`、`Level01_FirstFloor_Structure`、`Level02_SecondFloor_Structure`、`01_Slabs`、`03_SunkenDanceFloor...`）。名字里带「墙 / wall」的根节点永远不会被当地板（`1_Wall` 就是靠这条排除的）。没有活动渲染体/碰撞体的空壳根节点会被跳过。
- 导入的一楼模型没有碰撞体（ModelImporter `addColliders` = 0），所以电机发现地板根节点下的 MeshFilter 没有碰撞体时会补一个 `isTrigger` 的 MeshCollider：**只参与射线查询**，不改变现在「鬼能穿过墙」的阻挡行为。以后若要被墙挡住，需要另行给模型加实体碰撞（或把导入设置改成生成碰撞体），漂浮跟地逻辑不用改。
- 传送（`Teleport`，切楼层、附身返回、调试调用）后立刻按新位置的地板重新落位，不会从旧高度慢慢飘过去。
- 跟随镜头 `PrankCameraRig` 每帧跟玩家位置，所以高度变化会自动带上镜头，不需要额外改相机。

### 拆分地板与墙（重新摆模型时）

代码里没有任何地方把「一楼」当墙用，它只被当作**地板**：镜头左右转动范围、鬼的高度探测、检查脚本的测量包围盒。墙相关的代码只认旧白盒组 `02_BlackPlanLines_Walls_2m_80mm`（墙体遮挡淡出、碰撞体修补、撞墙测试）。

真正的问题是一楼模型把地板和墙合在一个 mesh 里，分不清水平面到底属于地板还是墙顶。所以地板改成**显式声明**，不再靠猜：

1. 在 Unity 里选中地板对象，跑菜单 **Ghost Party > Level > Mark Selection As Floor Surface**（等价于手动加 `GhostFloorSurface` 组件），保存场景。
2. 墙对象不用挂这个组件，也**不需要碰撞体**——鬼本来就能穿墙；墙上的高度探测会被竖直法线过滤掉。
3. 摆好后先跑 **Ghost Party > Level > Report Floor And Wall Sources**，Console 会列出哪些对象被当作地板、哪些被排除、哪些会在运行时补 query-only 的 MeshCollider。
4. 再点 Play 或 **Ghost Party > Player > Run Floor Hover Play Checks** 验收。

拆完不用改任何代码：地板组件优先级最高，名字随便取。命名习惯上，让墙名里带「墙 / wall」会更保险（解析旧名字时会跳过这类根节点）。

### 墙体遮挡：圆形裁切（整块墙）

旧做法是射线找出挡在镜头和鬼之间的**那一块墙片**，把它的材质换成半透明克隆。墙现在是一整块 mesh，这种“按片淡出”没有意义了（射线只会命中同一个 Renderer），所以改成在 shader 里按**屏幕空间**裁一个圆——就是镜头投影上的一个圆，以鬼的投影点为圆心：

- 墙材质用 `GhostParty/DecorationTransparent`（就是 decoration 那个 shader，新增了 `_GhostCutRadius` / `_GhostCutFeather` / `_GhostCutFill` / `_GhostCutPos` / `_GhostCutDistance`）。默认半径 0 = 完全关闭，所以共用这个 shader 的装饰道具不受影响——属性是由 `GhostWallCutout` 通过 MaterialPropertyBlock 只写进墙的 Renderer。
- 圆内先被裁掉（第一遍，保证鬼一定看得见），再用第二遍把它按 `_GhostCutFill` 画成一层半透明墙（默认 0.18，接近原来 0.2 的观感；设 0 就是干净的洞）。参数在墙上的 `GhostWallCutout` 上调：`Screen Radius` 0.22（屏幕高度的比例）、`Feather` 0.08、`Interior Alpha` 0.18。
- `GhostWallCutout`（挂在墙根节点上，例如 `1_Wall`）每帧把**玩家投影到摄像机的 viewport 坐标**、半径、羽化、圆内透明度写进墙的 Renderer。shader 把片元的 screen UV 和这个点相减、乘宽高比校正，再和半径比较——所以它在任何机位下都是屏幕上的正圆，不是世界里的圆柱或球；半径以屏幕高度比例计，跟分辨率无关。
- 圆只在「镜头与鬼之间」那一半生效：比较片元到摄像机的距离和鬼到摄像机的距离（`_GhostCutDistance`），所以鬼站在墙前面时，它身后的墙不会跟着破一个洞。
- 边界用 2×2 有序抖动裁掉（不是 alpha 混合），所以整块墙不用进透明队列，不会有排序问题；开着 MSAA 时软边更细。
- 材质不是这个 shader 也行：`GhostWallCutout` 会在运行时给墙的每个材质槽生成一份 decoration shader 的副本（保留贴图和 tint），原资产不动，Console 会打一条日志。出包时记得这个 shader 需要被某个材质（或 Always Included Shaders）引用，否则会被剥离。
- 只用白盒墙片（`02_BlackPlanLines_Walls_2m_80mm` 存在且激活）的旧场景仍走原来的 `WhiteboxWallOcclusion` 按片淡出，二楼不受影响。
- 墙对象不用挂碰撞体，也不影响“鬼可以穿墙”。

组件怎么挂：进入 Play 时 `WhiteboxPlayable` 会自动找名字里带「墙 / wall」的根节点并挂上；也可以选中墙对象跑菜单 **Ghost Party > Level > Attach Wall Cutout To Selection**。诊断用 **Ghost Party > Level > Report Wall Cutout**（会列出墙体 renderer 用的 shader 以及是否支持裁切）。如果 Console 报 “has no _GhostCutRadius property”，就是墙材质还停在 Standard，换成 `GhostParty/DecorationTransparent` 即可。

### 参数（player prefab 根节点 GhostPlayerMotor）

| 字段 | 默认 | 作用 |
| --- | --- | --- |
| Hover Height | 0.5 | 根节点到地板面的距离；调大就是「浮得更高」 |
| Probe Above / Probe Depth | 2.5 / 6 | 射线起点高度与最深探测距离，要能覆盖凹陷与台阶 |
| Max Step Up | 2.2 | 最多向上跟随多高的面；再高的面当墙，不当地板 |
| Follow Smooth Time / Max Vertical Speed | 0.12 / 5 | 升降手感，越大越「重」 |
| Snap Distance | 2.5 | 误差超过这个值直接吸附（传送用） |
| Floor Roots | 空 | 手动指定地板根节点；空则先用 `GhostFloorSurface` 标记，再退回旧名字 |

### 验证

菜单 **Ghost Party > Player > Run Floor Hover Play Checks**（单场景一楼）会实测：地板碰撞体数量、平层/最低面高度、从平层走进凹陷的逐帧高度采样、走出凹陷回升、最大单帧位移（确认是滑行不是吸附），结果写入 `Logs/PlayerPrefab/floor-hover-checks.json`。这只是程序化断言，手动走进凹陷看漂浮手感仍要人工验收。

## 验证方式

菜单 Ghost Party > Player > Run Ghost Art Play Checks：运行一楼、SampleScene、二楼、再次一楼四次独立 Play，会恢复原打开场景和窗口状态。检查唯一预制体玩家、保存引用、动画与翻转、6 秒顶 8cm 墙、斜向滑墙、大帧位移、真实场景墙体，以及附身重试与退出后恢复。结果位于 Logs/PlayerPrefab/play-checks.json；场景绑定与墙体实际包围盒位于 Logs/PlayerPrefab/build-report.json。

这些是 Unity 实际运行的程序化检查。真实键鼠操作、视觉观感与完整手动通关结果须单独记录，不能因运行时断言通过就标为手动验收通过。

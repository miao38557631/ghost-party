# 基础玩法与窗帘 · 开发用流程 v1.3

更新日期：2026-10-20

这是当前讨论确定的**目标玩法**，供窗帘恶作剧开发与沟通使用。网页演示只验证流程和输入手感，不等于 Unity 已实现；动作占拍、判定窗口、音效与震动强度均可在实机中调整。旧版“包裹客人再抽打”的步骤已撤销。

## 1. 一局中的位置

鬼在 2.5D 别墅里自由飞行，节奏小交互与主恶作剧共用持续播放的 BGM。靠近客厅窗帘和客人后进入特写。完成恶作剧时，镜头回到地图，客人承接最后一击的方向尖叫着离开。屋内还有客人时，玩家继续找下一个目标。

## 2. 本段使用的基础输入

| 输入 | 鼠标演示 | 用在窗帘上的意思 |
|---|---|---|
| 点按 | 左键点一下 | 连续三拍点窗吸引；靠近期间点窗帘让鬼飞入 |
| 按住与松开 | 左键按住，完成后松开 | 抓住窗帘尾巴并在整段挥打中保持抓握；收尾放开 |
| 定向移动 | 按住左键向提示方向滑动 | 连续左右抽打与最后的蓄力反抽 |
| 路径移动 | 从高亮起点按住，沿可见路径拖动 | 首抽先把窗帘拉到左侧，再在下一拍反向抽回 |

三次敲窗点按、靠近期间的一次窗帘点按，以及后续挥打都使用这四种基础输入的组合，不新增专用按键。路径移动有可见轨道和明确的抓取起点，不能在任意位置按下后随便拖；第一巴掌跨两拍，第一拍向左拉、第二拍保持按住反向向右抽。**右抽完成才算命中**，不能在蓄力拍就播放击中反应。定向移动的提示也要清楚显示方向，左右连抽期间不反复松开鼠标。手柄映射与震动仍待实机确定。

## 3. 窗帘的演出逻辑

1. **三拍吸引。** 玩家在连续三拍各点一次窗户。每次敲窗都有反馈，第三下后附近客人注意到异常，开始朝窗边走。
2. **靠近与进入窗帘。** NPC 靠近不计交互拍数，可能跨越任意数量的 BGM 拍；音乐始终继续。在他走来的期间，玩家点一下窗帘，隐形鬼飞入布中。这个点按有提示，但不要求卡在特定一拍，也不会因为 NPC 仍在走就算漏拍。**NPC 到位且鬼已进入窗帘**后，才进入 2·1 的抓尾巴动作。
3. **第一巴掌。** 窗帘尾巴出现高亮抓取点及可见左右路径。玩家抓住尾巴先拉到左边，再保持抓住，下一拍反向往右抽。客人被抽得在原地转一圈，头顶开始冒星星。旋转和冒星星留自动演出时间。
4. **左右连抽。** 鬼始终抓着窗帘，玩家跟着同一 BGM 的拍点交替向左、向右滑动。每次有效挥打都由窗帘动作、命中声、NPC 受击和适量震动共同反馈；后续几组逐渐加大动作与反应。这里可以做得解压，但不要把一个方向的预备动作误表现为已命中。
5. **蓄力抽飞。** 最后先向左拉住蓄力，停住一拍，不命中；下一拍反向向右重抽。NPC 沿抽出的方向飞离特写，玩家松开窗帘。回到地图后，客人踉跄、捂脸尖叫着逃走。退场不用再输入。

## 4. 首版逐拍示意

下表是**顺利完成时的暂定相对拍位**。第一段只有连续三拍敲窗，之后的 NPC 靠近是非计拍过门；不能把它当作“1·4”来限时或判漏拍。到位后从 2·1 开始按四拍小节示意。每个动作和受击动画可以跨更多拍；失败会延长当前步骤，BGM 不停止。研发时以演出逻辑为先，不把四拍表锁成最终动画时长。

| 小节·拍 | 玩家输入 | 画面 / 判定 |
|---|---|---|
| 1·1 | 第一次点按窗户 | 第一下敲窗 |
| 1·2 | 第二次点按窗户 | 第二下敲窗，NPC 注意到声音 |
| 1·3 | 第三次点按窗户 | 第三下敲窗，NPC 开始靠近 |
| 靠近过门（不计拍） | 期间点按一次窗帘；其余时间等客人到位 | 鬼飞入窗帘；NPC 走近、探头查看；两者完成后进入 2·1 |
| 2·1 | 从高亮尾巴抓住，沿路径向左拉 | 布角拉到左侧，蓄势；尚未击中 |
| 2·2 | 不松手，沿路径反向向右抽 | 第一巴掌命中 |
| 2·3 | 无输入 | NPC 原地转一整圈 |
| 2·4 | 无输入 | NPC 停住，头顶冒星星 |
| 3·1～4 | 保持抓住；左、右、左、右 | 第一组连抽，客人从疑惑转为恼火 |
| 4·1～4 | 保持抓住；左、右、左、右 | 第二组连抽，挥幅、音效和受击反应升级 |
| 5·1～2 | 保持抓住；左、右 | 最后一组连抽 |
| 5·3 | 向左拉住蓄力 | 停住、预备重击；这一拍不命中 |
| 5·4 | 反向向右重抽，完成后松开 | 重击、NPC 飞出；接地图退场 |

## 5. 提示、失败和实现边界

- 当前需要输入的拍子提前用**颜色、图标和方向动画**提示；自动演出拍不显示操作提示。靠近过门中的点窗帘只提示目标，不作卡拍判定。提示跟 BGM 同步渐入渐出，不让玩家读一整串谱面。
- 没按或按错时留在当前操作，音乐继续，下一次合适的拍点重试；不让整段动画自行播到下一操作。首抽两拍的连续抓握如何在失败后重新抓取，可由程序先做易理解的方案，再实机调整。
- 输入有效时窗帘立即跟手；命中反馈接在有效挥打上。失败不能播出成功受击、星星或抽飞。NPC 旋转、冒星星、走近和退场是自动演出。
- 三拍敲窗、非计拍靠近与点窗帘、抓尾巴、两拍首抽、自动反应、左右连抽、蓄力反抽都应作为可调整的阶段。拍数、重复次数、提示提前量、判定宽度以及震动曲线都可改，不要由这份示意表写死。
- 网页里的矢量演出是沟通用示意；Unity 具体完成度需以当前工程实机为准。旧 Unity 原型和早期玩法文档不能作为这版窗帘流程的依据。

# 基础玩法与窗帘 · v1.0 精简前存档

更新日期：2026-10-09

本版变更：鼠标的“定向移动”和“路径移动”合并为“沿轨迹移动”。必须按住起点圆并沿可见轨迹拖动；取消鼠标任意位置起手、只检查相对方向的旧设计。以下未落实的轨迹衔接与手柄适配不得按旧规则擅自补齐。

本文正文是策划要求，供开发实现与试玩验收，不是一份问卷。基础操作以网页策划案为基础；窗帘在 Unity 现有实例上调整。尚未明确的少数问题集中在文末，代码现状放在附录，不与目标玩法混写。

范围仅包含基础玩法和窗帘，以及围绕窗帘完善的提示、判定、镜头和漏拍机制。不展开物品选择／附身系统、其他恶作剧和地图推进，但保留 E 提示与进入特写的表现。

**正文写明的要求不代表已经实现。** 数值与技术方案由程序提出，结合试玩调整。用户填写原稿保存在 `Archive/基础玩法与窗帘_v0.5_用户填写原稿.md`，此前原稿也继续保留。

## 1. 基础玩法

玩家跟着音乐和操作图标完成恶作剧：

> 看当前操作和下一步预告 → 按节奏操作 → 成功进入下一步 → 失败重试当前操作 → 连续漏拍太多，NPC 挣脱。

提示要让玩家知道三件事：**做什么、什么时候做、需要持续多久。** 不要求读谱或理解音符术语。

- 本阶段只做整拍操作，半拍暂不制作。
- 只给当前操作和紧邻下一步的预告，不增加长串谱面或倒计时环。
- 自动演出不需要玩家操作，不计算漏拍。
- 音乐、判定和提示共用同一节奏时钟，不以动画结束来判成功。

## 2. 基础操作与按键

### 2.1 键鼠与 Xbox 手柄

| 基础操作 | 键鼠 | Xbox 手柄 | 用途 |
|---|---|---|---|
| A01 点按 | 点一下鼠标左键 | 点按 A | 一次短促动作 |
| A02 按住与松开 | 按住左键，持续指定拍数后按拍松开 | 按住 A，按提示松开 | 维持一段时间的动作 |
| A03 沿轨迹移动 | 在起点圆按住左键，拖着圆沿轨迹到终点 | 原映射 RT＋左摇杆保留；轨迹操控方式待适配 | 直线、转弯或连续分段轨迹 |

基础操作现在为三类：点按、按住与松开、沿轨迹移动。A04 不再作为独立类型；原来的转弯路径属于 A03 的连续分段轨迹。

手柄已经确定的组合规则保留：只有按住 RT 的同时移动左摇杆，才触发移动操作。RT 对应按住左键，松 RT 对应松左键；单独按 RT 或单独移动摇杆不能触发移动。手柄如何控制可见圆、选中起点及沿线移动尚需重新适配，不能把旧自由方向检测直接当成新版轨迹玩法。

RT 按住时，摇杆回中也属于移动，像鼠标往回移动一样，参与当前操作的正常判定；不因它是回中或机械回弹而豁免。回中不等于松开左键，也不一律失败，结果按当前步骤的方向、路径顺序、已达标状态和保持容错规则决定。玩家要让回中不参与移动判定，应先松开 RT，再回中；松 RT 对正在进行的步骤仍按对应松手规则处理。

设计以玩家左拇指持续操纵左摇杆为正常姿势，不把每次推动后离开摇杆、让它自行回正作为必需步骤。手柄功能不列为已实现，震动另行设计。

点按和普通按住操作不要求抓住轨迹圆；**沿轨迹移动必须从可拖动的起点圆开始，不能在任意位置起手。** 轨迹上的操作圆与窗帘旁白底提示图标不是同一个对象。点击 UI 按钮不同时算玩法输入。

连续点按、左右交替、拖动后保持按住是基础操作的组合。“包裹”“挥打”“蓄力”是对应表现，不增加新的基础操作类型。

### 2.2 点按

在目标拍允许的早／晚范围内点按，成功进入下一步；太早或太晚不成功。

**不做提前输入缓存。** 玩家在有效范围外点的一下，不会留到之后自动判成功。有效范围内稍早点按是正常容错，不是预输入。

短暂点击冷却期间忽略额外点击，冷却数值由程序给初始值并试玩，不能吞掉下一拍的正常操作。自动演出中的多余点击不推动流程。

### 2.3 按住与松开

持续拍数由具体步骤设置。玩家持续按住，在指定结束拍松开；过早松开判失败。

松开初始允许范围采用**目标拍前后各 0.3 拍**。允许范围内稍早松开仍算成功；只有早于范围才算提前失败。此处以用户最新明确的“前 0.3、后 0.3”为准，合计为 0.6 拍，不再写“合计 1 拍”。数值可试玩调整。

持续按住也可以与移动组合：窗帘最后蓄力就是先左下拖，再保持按住，不要求先松手重新按。

### 2.4 沿轨迹移动

画面显示可拖动的起点圆、完整轨迹与终点。玩家在起点圆上按住左键，移动鼠标拖着圆沿线走到终点。

- 拖动时圆的位置跟随鼠标，玩家能直接看到自己的操作位置，不是只有箭头却看不见鼠标在做什么。
- 直线与带转弯的轨迹共用一种基础操作；转弯是连续分段移动，不再单列“路径移动”。
- 需要沿轨迹完成，不允许从起点直接跳到终点、跳过中间路段，也不只用一个方向距离判断成功。
- 圆的可见跟随不能靠强行吸附到线上掩盖玩家实际偏离。偏离怎么容错、是否限制拖动范围，先提方案试玩，不自动锁定“一偏就失败”。
- 节奏要求保留：按当前步骤的开始、分段和结束提示卡拍。轨迹解决往哪里拖，不取消节奏判定；提前到终点与拍点如何衔接见附录 B。
- 转弯轨迹中途失败，整条当前轨迹重来，不回滚整轮窗帘或音乐。
- 最后甩出不强制另设松手成功条件；拖动与保持按住仍可以组合。

旧的“任意鼠标位置作为新起点”“拖够方向距离就记住成功准备”“拖得多远都允许”不再是新版鼠标轨迹规则。连续挥打如何连接轨迹、是否保持按住跨步骤，在有可见起终点的前提下另行落实，不能照搬旧起点采样。

## 3. 失败与重试

- 失败不跳过当前操作，换到下一目标拍重试，BGM 不倒退。
- 拖动失败的回弹／恢复持续 1 拍；恢复期间不缓存提前输入。
- 轨迹失败后清除本次拖动进度，重新显示当前轨迹的起点与终点，不把任意鼠标位置当成轨迹起点。
- 旧动作不能打断回弹，也不能恢复后自动再次达标。重试是否需要重新抓起点圆，或允许按住恢复，见附录 B；不套用旧“拍前 0.3 拍采任意位置”的自由拖动方式。
- 演出恢复与重试时间需统一安排，不能出现提示能按但系统仍锁输入的情况。

## 4. BGM 与难度

### 4.1 音乐

**当前 Unity 播放的音乐就是最终 BGM，不换曲。** 是否由代码生成不影响其正式使用地位。

默认 112 BPM、四拍一小节、32 拍循环。现有 `BuildAudio()` 生成并播放这段音乐。音乐中的八分踩镲不代表玩家需要半拍操作。

进入挑战预留准备时间后，从下一整拍开始；暂不额外做乐句对齐。判定与节拍提示共用音频时钟，并保持输出延迟校准能力。

### 4.2 判定与距离

简单模式比普通更宽松。沿用当前试玩参数作为初始参考，不一次锁定所有最终数值。

| 参考项 | 普通 | 简单 |
|---|---|---|
| 点按窗口 | 目标拍前后各 0.30 拍 | 前后各 0.42 拍 |
| 当前代码的拖动结算窗口 | 目标拍到目标拍后 0.30 拍 | 到目标拍后 0.42 拍 |
| 水平／竖直拖动距离 | 对应屏幕宽／高的 4% | 2.5% |

在 112 BPM 下，0.30 拍约 161 ms，0.42 拍约 225 ms。拖动窗口上表仅记录现有代码参考，新版起点和卡拍方式明确后由程序调整，不能直接当成新版全部规则。

距离单位、设备适配、冷却与镜头数值交给程序，试玩关注太严／太松、拖太远／太容易误触即可。

## 5. 窗帘完整流程

### 5.1 演出顺序

五组挥打包含最后的蓄力甩出：**四组普通左／右＋一组左下蓄力／右上甩出。** NPC 靠近占 2 拍。

下表为顺利完成时的流程安排，拍号相对本轮挑战，不是歌曲绝对拍号；失败会插入重试，不能固定按绝对歌曲拍号继续往下走。

| 流程拍位 | 玩家操作 | 演出 |
|---|---|---|
| 1 | 点按 | 窗帘挑动，吸引注意 |
| 2 | 再点按 | 再次吸引注意 |
| 3 | 不操作 | 自动抬起窗帘，1 拍 |
| 4～5 | 不操作 | NPC 靠近，2 拍 |
| 6 | 按住向右 → | 开始包裹 |
| 7 | 向下 ↓ | 拉紧，完成包裹 |
| 8 | 不操作 | 包裹完成演出，额外 1 拍 |
| 9 | 向左 ← | 第一组左巴掌 |
| 10 | 向右 → | 第一组右巴掌 |
| 11 | 向左 ← | 第二组左巴掌 |
| 12 | 向右 → | 第二组右巴掌 |
| 13 | 向左 ← | 第三组左巴掌 |
| 14 | 向右 → | 第三组右巴掌 |
| 15 | 向左 ← | 第四组左巴掌 |
| 16 | 向右 → | 第四组右巴掌 |
| 17 | 向左下 ↙ | 最后一组：左下拖动蓄力 |
| 18 | 保持按住，提示 `-` | 维持蓄力姿态 |
| 19 | 向右上 ↗ | 甩出，NPC 飞出，操作完成 |

表中普通操作暂按每拍一项排列；多拍动作的开始／结束采样规则需程序统一落实，不能因文字拍位理解不同又额外增加未提示的操作拍。

### 5.2 最后蓄力

- 共 2 拍：左下移动 1 拍，然后保持按住 1 拍。保持阶段不要求继续往左下拉。
- 允许正常小幅鼠标抖动；明显反向超过容错范围算中断，松手也算中断。
- 中断后失败，重新从左下蓄力开始，不跳到甩出。
- 保持以此前有效、卡拍的按住／左下操作为前提，不额外要求重新按下一次。保持这拍成功时，连续漏拍和圆环清零；完成后下一拍右上甩出，不强制松手判成功。
- 不自行新增力度条。反向容错数值由程序给方案、共同试玩。

第 17 拍主提示为 ↙、预告为 `-`；第 18 拍主提示为 `-`、预告为 ↗。`-` 暂表示“保持按住”，不是空拍或自动演出。正式保持图标待平面设计，不妨碍先做原型。

## 6. 出手、击中与音效

- 有效操作开始，窗帘出手和轻微镜头反馈立即响应，不等成功判定。
- 成功后接击中、NPC 受击和巴掌音效，不从头重播出手。
- 提前在允许时段完成条件时，击中落在目标拍；窗口内稍晚完成时确认成功就击中，允许略晚。不缓存有效操作时段之外的输入。
- 失败不播成功击中、受击和巴掌音效。已出手就打空／回弹；没操作不凭空出手。
- 成功立即更新当前提示和预告，旧动作收尾不挡下一次输入。
- 优先保证跟手、成功有节奏感、失败结果清楚；失败动画不强求精确踩拍。

动画长度、过渡和音效资源由制作提出方案，实机调整。

## 7. 连续漏拍与挣脱

| 难度 | 连续漏几拍走一格 | 四格满后的结果 |
|---|---|---|
| 普通 | 2 拍 | 连续漏 8 拍，NPC 挣脱 |
| 简单 | 3 拍 | 连续漏 12 拍，NPC 挣脱 |

- 任意一次有效手动步骤成功，连续漏拍和绿色圆环全部清零，包括未凑成一格的漏拍。
- 自动演出不增加也不清零；完成或挣脱过场不再计数。
- 漏拍指可操作的拍子过去却没完成要求，且当时不在自动演出中。合法持续按住属于操作，不因没有新的点击或位移就算“没操作”。蓄力保持成功同样清零，不等最后甩出才清零。
- 过早操作／松手不直接增加一格，真正错过目标拍才记漏拍，同一目标拍不重复记。
- 游戏明显卡顿导致错过的拍不补罚玩家。恢复后保留当前步骤和圆环，给重新跟拍的准备时间。
- 卡顿识别阈值和恢复准备时长由程序给初始方案、试玩；普通轻微波动不自动免判。
- 圆环满时停止挑战，NPC 挣脱离开，不播放成功扇飞。镜头立即开始退回地图，过场后恢复地图游玩。

保持按住这一拍是手动步骤，不是自动演出，需检查是否持续按住；中断则按蓄力失败处理。

## 8. 提示表现

| 提示 | 规则 |
|---|---|
| 窗帘轻微挑动 | 未挑战时跟拍轻动，告诉玩家可玩；挑战后停止这层挑动 |
| E 圆圈 | 靠近时白底黑 E，跟拍快速放大缩回 |
| 进入特写 | E 换操作图标，不重叠；随构图稍向下移 |
| 当前操作大圆 | 白底黑图标，手动图标常驻，到拍点快速放大缩回 |
| 自动步骤的主圆 | 保留白背景，内部空白，不加小点 |
| 下一步小圆 | 主圆左下，70% 不透明度，显示紧邻下一步骤，不跟拍跳 |
| 下一步自动／没有下一步 | 预告小圆整体隐藏，包括背景，不跨过自动步骤预告更后的操作 |
| 保持按住 | 暂用 `-` 图标；作为可操作步骤正常显示及预告 |
| 成功／失败 | 成功立即切换；失败保留当前操作，等待重试 |
| 顶部节拍辅助 | 默认关闭，可开启；圆形高亮后变细长线，关闭不影响操作提示和判定 |
| 挣脱圆环 | NPC 旁四格绿色圆环，与操作圆分开 |

切换手柄后需要对应的按钮／操作提示，不能仍让玩家看鼠标或 E 键文字；进入挑战手柄按钮及具体图标资源另定，不扩展物品交互系统。

## 9. 镜头手感

- 特写角度固定，不随鼠标连续转视角。
- 按操作要求方向轻移，方向一致且有上限，不随甩动距离无限增大。
- 成功保留偏移，下一动作顺滑接上；失败快速回弹，不能旧动作重复触发。
- 点按轻微拉近再恢复，最后一击更明显。
- 圆环走一格，猛拉近、稍收一点，再保持压力。成功清零恢复压力缩放，不误取消成功动作反馈。
- 挣脱回地图；特写提示下移避免遮挡。

程序参考现有效果给参数并看实机，不让策划填写相机技术数值。镜头不顺和真实长帧需通过诊断分别排查。

## 10. 开发与配置要求

以窗帘为例，把操作类型、方向、顺序、重复次数、持续拍数和演出占拍做成可修改配置；改动后判定、图标、预告与演出同步变化。

例如把一步“向左拖”换成“点按”，不应分别去多处改判定和箭头。配置是一份操作清单，不要求复杂工具。数据结构和字段名由程序决定；当前只有一段 BGM，不做多曲目管理或 Excel 导入。

开发需要把以下职责分清，而不是只把大脚本拆成多个文件：

| 部分 | 负责什么 |
|---|---|
| 基础操作 | 识别点按、按住、松开、方向和顺序；键鼠／手柄表达同一操作 |
| 节奏判定 | 读取音乐时间，判断有效时机 |
| 流程清单 | 当前步骤、下一步、自动演出、失败重试 |
| 提示与表现 | 图标、演出、镜头、音效；不自行判成功 |
| 漏拍与重置 | 连续漏拍和退出／重开清理，不残留旧手势 |

难度、距离、镜头、提示数值集中维护方便调参。配置错误要指出哪一步有问题，不悄悄换另一种操作。未实现的基础操作明确列为待开发。

## 11. 试玩验收

- [ ] 顺利完成按第 5 节流程走：靠近 2 拍、包裹后演出 1 拍、四组普通巴掌、拖动后保持、最后甩出。
- [ ] 点按不缓存预输入；失败恢复也不缓存预输入。
- [ ] 基础操作合并为三类；直线与转弯均属沿轨迹移动，必须抓起点圆，圆随鼠标可见移动。
- [ ] 不能跳过轨迹中段直接到终点；偏离容错按试玩确认方案处理。
- [ ] 当前轨迹失败整条重来；蓄力中断从左下蓄力重来。
- [ ] 连续移动允许不松手，不额外插入松手操作拍；最后甩出无需松手判成功。
- [ ] 轨迹起点来自可见起点圆，不使用旧自由拖动的任意位置采样；连续步骤衔接遵守确认后的轨迹方案。

### Xbox 摇杆：已确认的规则与开发边界

本节以第 2.1 节为准，撤回上一版“按摇杆所在侧识别动作、回中单独结束、快速回中豁免”的预案。不是已实现功能。

| 情况 | 玩家操作 | 处理规则 |
|---|---|---|
| 定向／路径输入 | 按住 RT，再移动左摇杆 | 才识别方向移动；单独按 RT 或单独推摇杆不触发 |
| 连续左右 | RT 持续按住，拇指连续操纵摇杆 | 所有移动都参与当前规则，不要求拇指离开或每次强制回中 |
| RT 按住时回中 | 摇杆从偏移位置返回中心 | 当作普通回移，不等于松手，不豁免，也不自动判失败 |
| 想让回中不参与操作 | 先松 RT，再回中 | 松 RT 按左键松手规则处理，之后回中不产生移动玩法输入；不能借此豁免该步骤的提前松手失败 |
| 路径转向 | RT 按住，按规定顺序移动 | 正常检查方向顺序和节奏，回移也参与，不强制回中后重新开始 |
| 蓄力保持 | 左下达标后保持 RT 和摇杆姿态 | 允许小幅抖动；明显反向超过阈值或松 RT 按蓄力中断处理；回中不因机械回弹而免责 |
| 最后甩出 | 按住 RT，向右上移动 | 最后一击不要求额外松 RT 或回中才能成功 |

普通定向动作已经达标后反向仍保留的规则继续有效；路径和蓄力则使用各自规则。不能把“回中参与检测”误写成“所有回中都失败”。

程序不能简单把“摇杆当前在左侧”一直当作新左向动作，也不能只把穿过中心到右侧才叫右移：需要按 RT 激活期间的实际摇杆变化、对应步骤起点和阈值识别相对移动。例如左侧回中存在向右的变化，应正常进入当前规则，而不是丢弃。具体轴值换算与阈值由程序给方案、手柄实测；不套用鼠标像素数，也不新增玩法规则。

可以过滤小幅漂移／抖动，但不能以死区或防误触名义忽略整个回中过程。一个达标动作只使用一次，持续顶住不自动重复完成后续方向步骤。镜头继续沿当前操作方向做有上限反馈，不直接放大抖动。

程序实测左／右交替、同方向连续动作、路径回移、松 RT 后回中、蓄力反向容错。左拇指持续操作是本设计的正常使用前提，不把玩家每次松开摇杆作为必需流程。具体阈值由程序提出，策划看实机手感，不再填公式。

新版以可见轨迹起点为准，旧任意位置拍前采样规则停用。程序仍需确保同一段移动不被重复用于两拍，且连续操作不会被吞掉。

其余距离、反向抖动容错、镜头参数、冷却和卡顿阈值交给程序提方案、实机调，不再要求策划填写公式。
